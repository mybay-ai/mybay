## Where files come from

Files generated by an Agent inside its instance workspace may appear in chat messages and file management. Supported types can open in preview; other types are available for download only when policy permits.

A path must belong to the current instance workspace. The server validates instance identity, normalizes paths, and blocks traversal and cross-instance reads.

> [!NOTE]
> Text that looks like a path in chat is not automatically downloadable. The file must exist and pass path and type validation.

## Preview and download

If a file card is unavailable, check whether the file moved or was deleted, whether the administrator session is valid, whether the path belongs to this instance, and whether type and size satisfy policy. Download large or unsupported files and open them with a trusted local tool.

## Protect sensitive files

Do not share or export:

- `.env` and configuration containing environment secrets.
- Private keys, certificate keys, and model credentials.
- Logs containing Authorization headers or internal routing secrets.
- Archives from an untrusted or unknown source.

Server restrictions are a final safeguard; they do not replace least-privilege task design.

## Disk use

`DEFAULT_INSTANCE_DISK_MB` is a local-host protection default, not an externally billed allowance. Deliverables, attachments, caches, logs, task state, dependencies, and workspace content all increase use under `data/`.

Remove confirmed temporary files regularly. Download deliverables that must be retained before deleting an instance or workspace content.

## Backup and restore

Before upgrades, migration, or bulk cleanup, stop writes and back up `.env` together with the entire `data/` directory. Copying one database file can omit instance configuration, workspaces, and other runtime data.

```bash
docker compose stop
# Copy .env and data/ with your backup tool.
docker compose start
```

Backups may contain credentials and business files. Encrypt them and restrict access. After restoration, verify the instance list, file previews, and decryption of saved BYOK credentials.

## When a file does not open

Refresh the administrator session, inspect control-plane logs for path or permission errors, and confirm that the instance is not being deleted or rebuilt. Do not modify the URL to bypass path validation.

For other runtime issues, see [Common troubleshooting](/docs/troubleshooting/common).
